## D-001 AR을 MVP에 포함
- **배경:** PRD v1.0 초안에서는 AR이 MVP 제외 항목이었지만, 사용자가 핵심 기능으로 원했다.
- **결정:** AR 돌탑 보기, AR 드래그 쌓기, AR 사진 촬영을 MVP에 넣고 중요도를 "상"으로 둔다(DB-011~013). PRD 7장과 10장도 고쳤다.
- **결과:** 일정과 기술 리스크가 커진다. 착수 전에 PoC로 검증해야 한다(TASKS 참고).

## D-002 모바일 + 웹 단일 코드베이스
- **배경:** 모바일과 웹을 둘 다 지원해야 하고, AR도 필요하다.
- **대안:** Unity(웹 AR 불가), Flutter(웹 AR 거의 불가), 네이티브 + 별도 웹(비용 2배)
- **결정:** Expo(React Native) + expo-router + react-native-web, 3D는 React Three Fiber
- **결과:** 일반 화면과 3D는 코드를 공유하고, AR만 플랫폼별로 구현한다.

## D-003 AR 구현체 3개
- **결정:** `ARSession` 인터페이스 하나에 구현체 3개를 둔다. 네이티브는 ViroReact, 웹은 WebXR(`@react-three/xr`), WebXR을 지원하지 않는 브라우저(iOS Safari, PC)는 카메라 + 3D 겹치기(간이 AR). AR이 아예 안 되면 일반 3D로 대체한다.
- **주의:** ViroReact는 Expo Go에서 실행되지 않으므로 EAS Dev Build가 필요하다. 유지보수가 끊길 위험이 있어 교체할 수 있게 분리했다.

## D-004 백엔드 Supabase (폐기 → D-013으로 대체)
- **이유:** 초기에는 Supabase를 고려했으나, Spring Boot MSA 학습 및 확장을 위해 D-013으로 대체했다.

## D-005 응원 데이터 경량화
- **배경:** 사용자가 DB가 너무 커지는 걸 걱정했다.
- **결정:** `wishes.cheer_count`(정수)와 중복 방지용 `cheers(wish_id, user_id)`만 저장한다. 응원 텍스트는 없다. 응원할 때 쌓이는 돌은 클라이언트 연출이다.
- **추가:** 이루어졌거나 삭제된 지 90일이 지난 소원은 `cheers` 행을 정리한다.

## D-006 응원 수 공개 범위
- **결정:** 정확한 응원 수는 작성자 본인만 본다. 다른 사람에게는 `cheer_level` 0~3단계(빛나는 정도)만 보여준다.
- **이유:** PRD의 "좋아요 경쟁 대신 응원 문화"를 지키기 위해서다.

## D-007 로그인 방식
- **결정:** Apple / Kakao / Google / 게스트 4가지. 게스트는 자동 세션으로 시작하고, 소셜 계정에 연결하면 데이터가 그대로 남는다.

## D-008 닉네임

## D-009 돌탑 정의
- **결정:** `wishes.group_id IS NULL`이면 공개 돌탑(전체, 카테고리 필터 가능), 값이 있으면 그룹 돌탑이다.

## D-011 객체지향 계층 구조

## D-023 프로젝트 리브랜딩(`Wish Stone`), 표준 디렉토리 재편 및 비심판적 자유 배치 UX
- **배경:** 기존 `Stone Wish` 명칭을 `Wish Stone (위시 스톤)`으로 통일하고, 루트에 산재한 파일들을 업계 표준 구조로 정리하며, 중심에서 벗어났을 때 붉은색 경고로 사용자를 위축시키던 UI를 개선할 필요가 있었다.
- **결정:**
  1. 패키지명(`com.wishstone.*`), 앱 설정(`app.json`, `package.json`), 로컬스토리지 키(`wishstone_*`)를 일괄 `Wish Stone`으로 리브랜딩한다.
  2. 루트 디렉토리를 `src/`, `backend/`, `docs/`(`docs/spec/`), `scripts/` 구조로 표준화한다.
  3. 돌을 꼭 정중앙에 놓지 않아도 빨간 경고창을 띄우지 않고 부드러운 토스 블루/스카이 블루 착지 링과 평온한 안내 문구로 자유로운 돌 쌓기를 지원한다.

## D-024 반경 28m 선(Zen)의 정원 맵 확장 및 6-DoF 자유 카메라·포커스 글라이드·돌탑 복귀 HUD 도입
- **배경:** 반경 2m의 좁은 단상과 중심축 고정 각도 회전만으로는 공간적 해방감과 돌탑 탐험의 몰입감을 주기 어려웠다.
- **결정:**
  1. 지형을 반경 28m의 선(Zen)의 정원으로 확장하고, 9겹 카레산스이 모래 물결, 6개 디딤돌, 밤하늘 지수 안개(`fogExp2`), 24개 인스턴스드 반딧불 입자를 배치한다.
  2. `OrbitControls`의 자유 패닝(Pan)과 줌(1.2m~24.0m)을 활성화하되, 반경 15m 실린더 안전 경계 클램핑과 `[ 🎯 돌탑으로 복귀 ]` HUD 버튼을 두어 길 잃음을 방지한다.
  3. 돌 클릭 시 0.5초 지수 감쇠 포커스 글라이드로 시점을 부드럽게 이동시키고, 쌓기 화면에서는 돌 드래그 중 카메라 조작을 잠가 제스처 간섭을 원천 차단한다.

## D-025 무게중심 편심비 3대 존 모델, 감쇠 조화 진동 마이크로 워블 및 쿨롱 경사면 슬립 물리 고도화
- **배경:** 무게중심이 어긋나도 돌이 순간접착제처럼 뻣뻣하게 서 있어 돌탑 쌓기 특유의 아슬아슬한 긴장감과 물리적 리얼리티가 부족했다.
- **결정:**
  1. 볼록 껍질 지지면 반경 대비 무게중심 편심비($\eta = d_{\text{ecc}} / R_{\text{support}}$)를 기준으로 안정($\eta < 0.40$), 긴장 워블($0.40 \le \eta \le 0.90$), 전복($\eta > 0.90$) 3단계 존을 확립한다.
  2. 긴장 워블 구간에서는 언더댐핑 감쇠 조화 진동($\theta(t) = \theta_0 e^{-\zeta \omega_n t} \cos(\omega_d t)$, $\zeta = 0.30, \omega_n = 20\text{ rad/s}$)을 적용해 뒤뚱거리다 안착하는 연출을 구현한다.
  3. 지지면 경사각이 임계 정지마찰각($\approx 26.6^\circ$, $\mu_s \approx 0.50$)을 초과하면 쿨롱 마찰 슬립 가속도($a = g(\sin\theta - \mu_k\cos\theta)$)로 미끄러져 내려가도록 한다.

## D-026 구면 조화 기반 자연 강자갈(River Pebble) 정제, 12종 천연 광물 팔레트 및 랜덤 리롤 UI 도입
- **배경:** 기형적이거나 각진 다면체 돌 형태를 없애고 자연스러운 강돌(조약돌) 감성을 살리며, 유저가 원하는 돌을 다시 뽑을 수 있는 기능이 요구되었다.
- **결정:**
  1. `pebbleGeometrySpec.ts`를 통해 하단 안착면 평탄화($y = -H_y$)와 부드러운 법선(`flatShading: false`)이 적용된 구면 조화 강자갈 지오메트리를 생성하되, 물리 충돌 바운딩 박스($\text{halfExtents} = \text{scale} \times 0.25$) 불변식을 유지한다.
  2. 현무암, 백운석, 황토 규암 등 12종의 자연 광물 팔레트를 적용한다.
  3. `StackStoneController.rerollStone()` 및 `[ 🎲 다른 돌 찾아보기 ]` UI 버튼을 돌 선택 화면과 쌓기 화면에 통합하여 캔버스 깜빡임 없이 즉각 새로운 돌을 뽑을 수 있게 한다.
